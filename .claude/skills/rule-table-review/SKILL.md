# 輸出ルール表の見直し（月1回）

輸出の決まりは変わります。この Skill は、`rules/輸出ルール表.md` の各項目が、今も出どころの公的資料と合っているかを確かめ、**直し案の下書き**を作ります。表そのものは、人が下書きを確かめて「入れてよい」と言うまで書き換えません。

## 進め方

1. **範囲を決める。** 頼まれた国（例：「中国だけ」「0-1〜0-4」）があればそこだけ。指定が無ければ全項目。
2. **項目を集める。** 表から、範囲の項目の「#・(1) 要件・(5) 出どころ」を抜き出す。表の冒頭の「確認日」も控える。
   - (5) が「同上」の項目は、すぐ上の項目の出どころを使う。
3. **国ごとにサブエージェントに分けて、並行して調べる。** `rule-source-checker` サブエージェントを国（入口の0番台・米国・EU・中国）ごとに1本ずつ、同時に呼ぶ。渡すもの：その国の項目の一覧（#・要件・出どころの文とURL）と、前回の確認日。
4. **結果を1枚にまとめる。** `rules/見直し/YYYY-MM-DD.md` に、次の形で書く。
   - 冒頭に、範囲・見た出どころの数・「変化あり」「開けなかった」の件数
   - **変化あり**：項目ごとに「今の表の文」「出どころの今の文（そのまま引用）」「直し案」「出どころのURLと確かめた日」
   - **開けなかった**：URL と理由（リンク切れ・PDFが読めない等）。代わりの資料の候補があれば添える
   - **変化なし**：項目番号だけ並べる
5. **人に見せて止まる。** 下書きの場所と、変化ありの件数を伝え、どれを表に入れるかを聞く。
6. **入れてよいと言われた分だけ、表を直す。** 直した項目の (5) に確かめた日と確かめ方の印（【原文】【当局ページ】など）を書き、表の冒頭の「確認日」を新しくする。古い資料に頼っていた項目は、古い旨を書き添える。
7. **表の形が崩れていないか確かめる。** 表を書き換えると、このリポジトリのフック（`.claude/settings.json`）が自動で `npm test` を流す。失敗したら、表の形（`#` 列＋6列、`## 国`、`### 箱`）を直してから終える。

## 守ること

- 根拠は出どころの公的資料の文だけ。記憶や一般知識で決まりを足したり変えたりしない。
- 引用は出どころの文をそのまま写す。言い換えない。
- 施行日がまだ先の変化は「これから変わる」として、施行日を必ず書く。
- 国や地域について政治的な言い方はしない。公表されている決まりと記録だけを書く。
- 緊急の輸入停止など、すぐ効く措置を見つけたら、下書きの一番上に書いて、すぐ人に知らせる。
